# 讲话首尾不丢字、手机声源不乱切(2026-11-12)

## 问题

1. 松开讲话键后最后几个字丢失。
2. 按下讲话键后最前面几个字丢失(豆包模式最明显)。
3. 在 Mac 上把声源切回「设备」(或刷固件、重连后),声源又自动跳到「手机」。

## 原因

- 松开即发静音:设备收到后只再发约 240 ms 淡出帧,而最后一个字往往还在嘴边、麦克风与蓝牙缓冲里。
  豆包自己监听讲话键,一松开就停录(实测松开后约 180 ms),话尾还在设备淡出、Mac 抖动缓冲
  (预缓冲 180 ms)与「只留本人声音」的 0.75 s 延后里,没播进 BlackHole。
- 豆包按**系统默认输入**录音。默认输入不是 BlackHole 时它听的是 Mac/耳机麦克风,
  蓝牙耳机还要切 HFP,开头必丢。另外豆包在按下后约 100 ms 才开始录,设备 codec 冷启动还要丢一帧上电瞬态。
- 设备模式下 Mac 也扫描配对过的 iPhone 广播,第一次看到就切到手机。iPhone 加入 PTT 频道后一直广播
  (后台也广播);而「是否见过」记在 `Uplink` 里,每次链路重建(重连、刷固件重启、点「重新连接」)
  都从「没见过」开始,于是第一条广播又被当成「手机刚打开」。原来的「切回设备就不再接管」
  只在设备在线时记下,也会在 5 秒没看到广播后被清掉。

## 改动

- `HomeModel.handleTalkKey`:松开后 0.3 s 才发静音;之后等设备静音、帧停 150 ms、抖动缓冲与本人声音过滤都播空,
  再加 80 ms 输出设备余量,最后统一收尾(最多 2.5 s)。话尾期间再按下:接着讲。
- `FnListener.holdsRelease`(豆包模式打开):扣住讲话键的松开事件,话尾播完由 `postHeldRelease()` 重发
  (时戳改为重发时刻,带标记让 tap 放行),最多扣 3 s;扣住期间按别的键先补发松开再按原顺序重发;
  扣住期间又按下,这次按下与扣住的松开一起吞掉,豆包看到的是一次没断的长按。停用监听/tap 被禁用时立即补发。
- 本地转文字:不再在设备报静音那一刻定稿,改由话尾流程收完再定稿;断链仍立即收尾,超时兜底改为 4 s。
- `makeDefaultInput`:豆包模式开启、音频出口重建时把系统默认输入设成 BlackHole。
- 手机自动跟随:「见过/消失时刻」存在 `HomeModel`,跨链路重建保留。只有新打开(消失或 App 启动后没出现满 1 分钟再出现,
  或在手机模式下 iPhone 点了停止后再打开)才自动切到手机;App 启动时已在广播的 iPhone 不算新打开;一直开着时 Mac 上切回设备一直有效。

## 未改

- 固件首帧上电瞬态仍整帧丢弃(约 60 ms)。codec 常开曾被怀疑导致豆包重复出字而回退
  (见[归档](../../archive/requirements/desk-voice-repeat-2026-11-06/README.md)),这次不动;
  开头主要靠默认输入设对解决,仍建议按下后稍停再开口。

## 验证

- `swift build`、`swift test`(新增 `phoneOnlyTakesOverWhenFreshlyOpened`)通过。
- 待真机确认:豆包模式与本地转文字的句首句尾完整;扣住松开期间按快捷键(如 ⌥ 组合)不串键。
